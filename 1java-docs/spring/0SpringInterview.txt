Factory pattern
	The Factory Design Pattern is a creational design pattern. Instead of letting the client directly create an object using new, a separate component is responsible for deciding which object to create and returning it.

BeanFactory
	BeanFactory is a Spring IoC container interface. It provides mechanisms for managing and retrieving beans. It may perform object creation internally, but its responsibility is broader than the traditional Factory Design Pattern.
Dependency injection
	Dependency Injection is a design pattern where a class receives its dependencies from an external container instead of creating them itself. In Spring Boot, the Spring IoC container creates and manages beans and injects their dependencies, usually through constructor injection. This reduces tight coupling, improves testability, and makes it easy to switch implementations.
Which type of injection do you prefer?
	Constructor injection, because dependencies are explicit, can be final, objects are fully initialized when created, 
	and it's easier to unit test.	
IOC 
	Normally, your application controls object creation. With Spring The control of object creation has moved from your application code to the framework. That's Inversion of Control.

how to instantiate a Spring IoC container
	The Spring Boot application starts through SpringApplication.run(). Spring Boot creates and initializes an ApplicationContext, which acts as the IoC container. It processes configuration, performs component scanning, registers bean definitions, creates and configures beans, resolves their dependencies, and performs dependency injection. Once the context is initialized, the application is ready to serve requests.
	
	Although Spring Boot normally does this for you, you can explicitly create an ApplicationContext.
	ApplicationContext context = new AnnotationConfigApplicationContext(AppConfig.class);
	OrderService service = context.getBean(OrderService.class);
how to solve Circular Dependency in spring
	First, I would identify why the circular dependency exists and refactor the design to remove the cycle. Circular dependencies often indicate that responsibilities between services are too tightly coupled. I might extract common functionality into another service or introduce an orchestration component so that dependencies have a clear direction. @Lazy can sometimes break the initialization cycle, but I would treat that as a workaround rather than the preferred solution. I would avoid enabling spring.main.allow-circular-references just to hide the problem.

Difference between Conroller and RestController
	The main difference is what Spring does with the return value from your controller method.
	@Controller is traditionally used for MVC applications that return views/pages.
	@RestController is used for REST APIs, where the response is normally JSON/XML/data rather than an HTML view.
	
StereoType Annotations
	@Service, @Component, @Repository @RestController are stereotype annotations
	In Spring, stereotype annotations are annotations that tell Spring: "This class is a component managed by the Spring IoC container, and this is the role it plays."
	Spring discovers the class through component scanning.
Stereotype vs @Bean

how to handle exceptions
	public class OrderNotFoundException extends RuntimeException {
		public OrderNotFoundException(String message) { super(message); } 	}
	@RestControllerAdvice
	public class GlobalExceptionHandler {
		@ExceptionHandler(OrderNotFoundException.class)
		public ResponseEntity<ErrorResponse> handleOrderNotFound( OrderNotFoundException ex) {
			ErrorResponse error = new ErrorResponse( "ORDER_NOT_FOUND", ex.getMessage() );
			return ResponseEntity.status(HttpStatus.NOT_FOUND).body(error);
		}
	}
	Checked exceptions compiler forces to you handle the exception either with throws keyword or try/catch
	IOException SQLException FileNotFoundException InterruptedException
	unchecked exception- compiler does not force you to handle
	NullPointerException IllegalArgumentException IllegalStateException IndexOutOfBoundsException RuntimeException
	all custom exceptions extends RuntimeException are unchecked exceptions 
	we use unceked exceptions for business logic exptions, we do not need to writr try/catch in every layer
	API is throwing checked exception we catch it and convert to uncheked exception
Rest security
	I use Spring Security to secure REST endpoints. Authentication can be implemented using JWT or OAuth2, depending on the architecture. After authentication, Spring Security uses roles or authorities for authorization.
	
	OAuth2
		in OAuth2, Your application never needs to receive the user's IDP password. Instead, IDP provides tokens that represent the user's authorization.
		After successful authentication/authorization, the authorization server gives the client an access token.
		Spring Security validates the token.
		OAuth2 is an authorization framework/protocol.
		JWT is a token format.
		An OAuth2 access token can be a JWT, but it doesn't have to be.
		OAuth2-Authorization — what can this application access?
		OpenID Connect (OIDC) -Authentication — who is the user?
		you're often dealing with OpenID Connect + OAuth2, not OAuth2 alone.
		Microsoft Entra ID
			ID Token → tells application who the user is
			Access Token → used to call APIs
		don't use the ID token as the bearer credential for your Spring Boot API. The API should receive and validate an access token intended for that API.
	You may need to configure CORS so the browser allows the Angular application to call your API.
	disabling CSRF is common for a stateless JWT API
